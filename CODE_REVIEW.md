# Код-ревью rustdesk-api-server

Дата: 2026-09-29. Проверялся весь код, кроме вендорной статики (layui, Django admin).

Пункты, помеченные **[проверено]**, воспроизведены на локальном запуске (Django 5.2, две учётные записи: администратор и обычный пользователь). Остальные найдены при чтении кода.

## Краткий итог

Проект работает как API-сервер для клиента RustDesk, но **для работы в интернете не готов**: CSRF отключён глобально, API клиента почти не проверяет авторизацию, в веб-интерфейсе нет проверки владельца устройства, а ссылки общего доступа не истекают. Также есть логические ошибки: статус «онлайн» считается неверно, при ошибках в формах страницы падают с 500, сервер не запускается без файла, которого нет в репозитории. Тестов нет.

## 🔴 Критично — безопасность

### 1. CSRF-защита отключена во всём проекте
`rustdesk_server_api/settings.py:49` — `CsrfViewMiddleware` закомментирован. Любой сайт, который откроет залогиненный пользователь (особенно администратор), может от его имени создавать ссылки общего доступа, назначать устройства и т. д. Удаление устройства (`/api/delete_peer?rid=…`, `api/views_front.py:531`) и принятие ссылки общего доступа вообще выполняются GET-запросом — хватит тега `<img>`.

**Исправление:** включить middleware, пометить `@csrf_exempt` только JSON-эндпоинты клиента в `views_api.py`, изменяющие действия перевести на POST, в шаблоны добавить `{% csrf_token %}`, в AJAX — заголовок `X-CSRFToken`.

### 2. Нет проверки владельца и прав администратора в веб-интерфейсе [проверено]
- `edit_peer` (GET, `views_front.py:483`) — `RustDeskPeer.objects.get(rid=rid)` без фильтра по `uid`: любой пользователь видит устройство другого пользователя по его ID.
- `assign_peer` (`views_front.py:497`) — только `@login_required`, без проверки `is_admin`: обычный пользователь может добавить любое устройство в адресную книгу любого пользователя (в тесте он добавил устройство администратора себе).
- `conn_log` / `file_log` (`views_front.py:413`, `:420`) — любой залогиненный пользователь видит журналы **всех** подключений и передач файлов (ссылка в меню скрыта, но сама страница доступна).

**Исправление:** фильтровать по `uid=request.user.id`, для административных страниц — `@user_passes_test(lambda u: u.is_admin)`.

### 3. Ссылки общего доступа не одноразовые и не истекают
`views_front.py:290` — при переходе по ссылке запись ищется только по `shash`, без проверки `is_used`/`is_expired`. Флаг «истекла» ставится лишь когда **владелец** открывает страницу `/api/share` (`check_sharelink_expired`). То есть ссылка из UI «на 15 минут, одноразовая» на деле работает бессрочно и для любого числа пользователей.

Там же: `check_sharelink_expired` сравнивает `timedelta.seconds` (см. п. 8).

### 4. Хранимый XSS в `msg.html`
`api/templates/msg.html:7` — `{% autoescape off %}`. В `msg` подставляются `peer.rid`, которые пользователь может записать произвольными через `POST /api/ab`. Получатель ссылки общего доступа выполнит внедрённый JavaScript. **Исправление:** убрать `autoescape off`, для переноса строк использовать `linebreaksbr` или разметку в шаблоне.

### 5. API клиента без аутентификации
- `/api/heartbeat` (`views_api.py:234`) — по одним лишь `id`+`uuid` продлевает токен, причём ставит `create_time` на 2 часа **в будущее**. Из-за условия `now_t > token.create_time else 0` (`views_api.py:48`) токен с периодическими heartbeat никогда не истекает.
- `/api/sysinfo` (`views_api.py:202`) — любой может создать или перезаписать запись об устройстве. При обновлении все ключи из JSON передаются в `.update(**postdata2)` (`views_api.py:230`) — можно записать любое поле модели (например, `create_time`), а неизвестный ключ вызывает 500.
- `/api/logout` — выходит по `id`+`uuid`, без токена.
- `/api/audit` — без аутентификации пишет произвольные записи в журналы.

### 6. Предсказуемые токены
`access_token` и `shash` = `sha256(str(time.time()) + SALT_CRED)` (`views_api.py:60`, `views_front.py:342`). Безопасность держится только на секретности соли, а два входа в одну миллисекунду дадут одинаковый токен. **Исправление:** `secrets.token_hex(32)`.

### 7. Опасные настройки
- `DEBUG = os.environ.get("DEBUG", False)` (`settings.py:28`) — строка `"False"` или `"0"` истинна, т. е. `DEBUG=False` **включает** отладку со страницами трассировки.
- `ALLOWED_HOSTS = ["*"]` (`settings.py:30`).
- Статика раздаётся через `django.views.static.serve` в продакшене (`urls.py:32`) — медленно и не рекомендуется Django.
- Скрытая регистрация: `POST /api/user_action?action=register` (`views_front.py:131`) создаёт пользователя любому анониму, хотя в `urls.py` регистрация закомментирована. GET на тот же адрес падает с 500 (нет шаблона `reg.html`). Если регистрация не нужна — удалить ветку.

## 🟠 Ошибки логики

### 8. `timedelta.seconds` вместо `total_seconds()`
`.seconds` — это только секунды внутри суток (0–86399), без дней. Затронуты:
- срок жизни токена — `views_api.py:48`;
- статус «онлайн» — `views_front.py:196`, `:227` (устройство, которое было в сети ровно сутки назад, показывается онлайн);
- срок жизни ссылки — `views_front.py:263`.

### 9. Статус «онлайн» считается неверно
- `get_single_info` (`views_front.py:202-204`) после подсчёта перезаписывает `status = 'X'` для **всех** устройств — в таблице пользователя статус всегда «X», хотя `online_count` посчитан.
- `get_all_info` (`views_front.py:227`) сравнивает текущее время с `update_time`, отформатированным как `'%Y-%m-%d'` (без времени) в `model_to_dict2` — фактически с полуночью.
- Там же `devices[peer.rid]['rust_user'] = user.username` (`:224`) — если владелец удалён, `user` равен `None` → `AttributeError` и падение главной страницы.

### 10. Падения с 500 [частично проверено]
- `/api/user_action` без `action` возвращает `None` → 500 **[проверено]**.
- `add_peer` с невалидной формой — переменная `rid` не определена (`views_front.py:455`) → `UnboundLocalError`.
- `edit_peer` / `assign_peer` с невалидной формой — функция возвращает `None` → 500.
- `edit_peer` GET — `.get(rid=…)` выбрасывает `MultipleObjectsReturned`, если устройство есть у нескольких пользователей (обычная ситуация после общего доступа), и `DoesNotExist` для несуществующего ID.
- `edit_peer` POST — `.get(rid=rid, uid=uid)` без обработки `DoesNotExist`.
- Эндпоинты `views_api.py` делают `json.loads(request.body)` и обращаются к `postdata['id']` без проверок — битый JSON или отсутствующее поле дают 500 **[проверено для `/api/audit`]**.
- `ab`: `int(x.tag_color)` (`views_api.py:132`) — нечисловой цвет, записанный через API, ломает загрузку адресной книги.

### 11. `POST /api/ab` всегда отвечает ошибкой
`views_api.py:196` — после успешного сохранения возвращается `{'code': 102, 'data': 'Error updating the address book'}` **[проверено]**. Кроме того, удаление старых и вставка новых записей не обёрнуты в `transaction.atomic()` — при ошибке в середине адресная книга будет потеряна. Пустой список устройств (`if peers:`) не сохраняется, т. е. последнее устройство удалить из клиента нельзя.

### 12. Длины полей
`RustDeskPeer.username`/`hostname` — 20/30 символов, `RustDesDevice.cpu`/`hostname`/`os` — 20, `ip` — 16 (IPv6 не помещается), `ShareLink.peers` — 20 символов (влезает ~2 ID). SQLite это не проверяет, но при переходе на PostgreSQL/MySQL запросы начнут падать или обрезать данные. Строки CPU и ОС почти всегда длиннее 20 символов.

### 13. Маршруты без якоря `$`
`api/urls.py` — `^ab`, `^login`, `^share` и т. д. совпадают с любым путём, начинающимся с этих букв (`/api/abcdef` → `ab`). Разбор хеша ссылки через `url.split('/')[-1]` (`views_front.py:289`) — следствие этого. Лучше `path('share/<str:shash>', …)`.

### 14. Проверка версии Django строками
`django.__version__.split('.')[0] >= '4'` (`urls.py`, `api/urls.py`) — строковое сравнение. Django < 4 давно не поддерживается; проще сразу использовать `re_path`/`path`.

## 🟡 Конфигурация и развёртывание

15. **Сервер не запускается из чистого клона.** `settings.py:15` безусловно импортирует `secret_config`, которого нет в репозитории (и он не описан). Повторный импорт в `suppress(ImportError)` в конце файла ничего не даёт. Лучше читать `SECRET_KEY`, `SALT_CRED`, `CSRF_TRUSTED_ORIGINS` из переменных окружения и падать с понятным сообщением.
16. **`db/db.sqlite3` в git** — и при этом без миграций 0002/0003: без `migrate` журналы не работают. Базу стоит убрать из репозитория и добавить в `.gitignore`.
17. **Две копии статики.** `static/` (исходники и `STATIC_ROOT` одновременно) и `static_root/` (нигде не используется). `STATIC_ROOT` не должен совпадать с каталогом исходников.
18. **Нефиксированные зависимости** — `requirements.txt` без версий.
19. **`USE_TZ = False`** при `TIME_ZONE = "UTC"` — времена хранятся «наивными», в интерфейсе показывается UTC.
20. **Отладочный вывод:** `print('debug', sys.argv)` на каждый запрос `/` (`views_front.py:98`), `print(all_info)` на главной (`:254`), `print(postdata)` в аудите. Заменить на `logging`.
21. **Контекст-процессор `api.util.settings`** делает запрос к БД на каждый рендер и пишет ошибку в лог для анонимов. Он дублирует `request.user`; тестовая переменная `context['test']` лишняя.
22. `UserProfile.REQUIRED_FIELDS = ['password']` — пароль не должен быть в этом списке; `has_perm` всегда возвращает `True`.

## 🔵 Качество кода

28. **Тестов нет** (`api/tests.py` пустой). В первую очередь стоит покрыть API клиента и проверки доступа.
29. **Импорты через `*`** по цепочке `views.py` → `views_front`/`views_api`; `EFFECTIVE_SECONDS` и `getStrSha256` приходят в `views_api` неявно. Много неиспользуемых импортов.
30. **`ModelAdmin` определены в `models_work.py`** — их место в `admin.py`.
31. **N+1 запросы:** `get_all_info` выполняет запрос `UserProfile` на каждое устройство; `get_conn_log`/`get_file_log` — два запроса на каждую запись журнала и загрузка всего журнала в память перед пагинацией. На больших журналах страницы будут очень медленными. Нужно сортировать и пагинировать через QuerySet (`order_by('-conn_start')`).
32. `model_to_dict2` пытается сделать `json.loads` для каждого строкового поля — строка `"123"` превратится в число, `"true"` в `True`.
33. Везде жёстко прописаны URL (`'/api/work'`, `login_url=…`) — лучше `reverse()` и `settings.LOGIN_URL`.
34. Опечатка в имени модели `RustDesDevice`; комментарии на китайском вперемешку с английскими.
35. `ConnLog.id`/`FileLog.id` объявлены как `IntegerField(primary_key=True)` вместо `AutoField` — в SQLite работает благодаря rowid, в других СУБД вставка без id упадёт.
